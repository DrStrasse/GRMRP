# GRM ADMIN PLATFORM — собственная админ-база сборки

**Версия:** Core 1.0.0 · Actions 1.0.0 · Panel 1.0.0 · дата 18.08.2026

Заказ владельца: своя административная база вместо «голого» ULX — с
собственным меню (сохранения, фракционный контроль, создание привилегий и
правка полномочий, модерация игроков), с читерскими возможностями
суперадмина и **полной синхронизацией с ULX/ULib**, чтобы ничего не сломать.

---

## 1. Что установлено

| Файл | Роль |
|---|---|
| `lua/autorun/sh_grm_admin_core.lua` | ядро: группы, права, иммунитет, хранение, мосты ULib/CAMI |
| `lua/autorun/server/sv_grm_admin_actions.lua` | действия: модерация и возможности суперадмина |
| `lua/autorun/client/cl_grm_admin_panel.lua` | меню `/admin` в стиле GRM |

Хранение: `data/grm_admin/groups.json`, `data/grm_admin/users.json`.

## 2. Модель прав

**Группа** — id, название, цвет, `inherit` (наследование), `immunity` (0..100),
флаги `admin` / `superadmin`, набор разрешённых прав.

**Право** — идентификатор вида `категория.действие`, название, категория,
уровень по умолчанию (`user` / `admin` / `superadmin`) и признак «опасное».

**Назначение** — SteamID64 → группа, срок (0 = бессрочно), заметка, кем выдано.

### Порядок проверки `GRM.Admin.Can(ply, "perm")`
1. Консоль сервера и суперадмин — всё.
2. Явное правило в группе или её родителях (`true` / `false`).
3. `*` в группе — всё.
4. Уровень `user` — всем.
5. Совместимость: если игрок админ движка/ULX, но его группы нет в реестре
   GRM (первый запуск), права уровня `admin` выдаются — чтобы не остаться без
   управления сервером.
6. CAMI: спрашиваем внешний админ-мод.

**Важно:** права уровня `admin` не выдаются автоматически всем админским
группам — нужна явная галочка. Иначе матрица полномочий не имела бы смысла
(модератор получал бы клетку и баны просто по факту «он админ»).

**Иммунитет:** действие к цели возможно, только если её иммунитет строго
меньше вашего. Суперадмин игнорирует это правило.

### Группы по умолчанию
| Группа | Иммунитет | Что может |
|---|---|---|
| `user` | 0 | ничего административного |
| `moderator` | 20 | меню, ТП к игроку/притянуть/вернуть, заморозка, мут чата и голоса, предупреждения, наблюдение |
| `admin` | 50 | всё выше + клетка, рагдолл, убить/воскресить, лечение, изъятие оружия, кик, фракционный контроль, очистка, модули |
| `superadmin` | 100 | всё, включая читерские возможности, правку групп и назначения |

## 3. Синхронизация с ULX/ULib (ничего не ломается)

* **Импорт при первом запуске** — группы `ULib.ucl.groups` и назначения
  `ULib.ucl.users` переносятся в GRM (один раз, флаг в users.json; повторить
  принудительно — `grm_admin_sync`).
* **Назначение группы** пишется сразу в три места: движок
  (`ply:SetUserGroup` — значит `IsAdmin()`/`IsSuperAdmin()` и все чужие
  проверки продолжают работать), `ULib.ucl.addUser` (ulx-команды и меню видят
  игрока) и `CAMI.SignalUserGroupChanged` (SAM, ServerGuard, DarkRP и прочие).
* **Обратная сторона:** если группу поменяли через ULX, GRM ловит
  `CAMI.PlayerUsergroupChanged` и записывает изменение у себя — базы не
  разъезжаются.
* **Права GRM видны снаружи:** каждое право регистрируется в CAMI как
  `grm_<право>`, а на запрос `CAMI.PlayerHasAccess` по такому имени отвечает
  GRM.
* **ULX-команда** `ulx grmadmin` (`!grmadmin`) открывает наше меню — админам
  не нужно переучиваться.
* **Кик и бан** отдаются `ULib.kick` / `ULib.ban`, если ULib установлен —
  одна база банов, никакого раздвоения. Без ULib используется движок.

## 4. Меню `/admin` (также `/админ`, консоль `grm_admin_panel`)

| Вкладка | Право | Содержимое |
|---|---|---|
| Игроки | `menu.open` | список онлайна с поиском, состояние (HP, броня, пинг, флаги мут/клетка/фриз/бог), все действия модерации, выдача группы |
| Привилегии | `acl.groups` | группы: создание, удаление, наследование, иммунитет, флаги; матрица полномочий по категориям |
| Назначения | `acl.assign` | кому какая группа выдана, срок, основание, кем выдано |
| Сохранения и карта | `server.persistence` | единое сохранение, сохранить/загрузить сейчас, пермы, аудит дверей, очистка пропов |
| Фракционный контроль | `server.factions` | организации, модели, вооружение, экономика, документы |
| Модули сборки | `menu.modules` | версии подсистем, очередь загрузки `grm_boot_status`, проверка звуков, синхронизация с ULX |
| Суперадмин | `cheat.god` | бог, невидимость, строительный режим, телепорт в прицел, заморозить/разморозить всех, очистка |

Вкладки без права **не создаются вообще** — не «серые кнопки».

## 5. Действия модерации

`goto` · `bring` · `return` · `tppos` · `freeze` · `mute` (чат) · `gag`
(голос) · `jail` (клетка на месте с возвратом и таймером) · `ragdoll`
(с наблюдением за телом и автоподъёмом) · `slay` · `respawn` · `heal`
(HP + броня) · `strip` · `spectate` · `warn` · `kick` · `ban`.

Возможности суперадмина: `god`, `cloak`, `speed`, `buildmode`, `freezeall`,
`unfreezeall`, `money` (выдать/списать), `item` (оружие или предмет
инвентаря), `cleanup` (очистка пропов).

Все действия: проверка права → проверка иммунитета → выполнение → запись в
`GRM.Audit` → уведомление обеим сторонам. Состояния снимаются при выходе и
смерти: клетки и рагдоллы не остаются на карте, замученный не «зависает».

## 6. Консольные команды

| Команда | Что делает |
|---|---|
| `grm_admin_panel` | открыть меню |
| `grm_admin_groups` | печать групп и их полномочий |
| `grm_admin_perms` | печать всех прав |
| `grm_admin_sync` | принудительный импорт из ULX + публикация в CAMI |
| `grm_admin_save_all` / `grm_admin_load_all` | сохранить/загрузить состояние карты и модулей |
| `grm_admin_cleanup` | очистка мусорных пропов |

---

## 7. Как модулям пользоваться

```
GRM.Admin.RegisterPerm("mymodule.edit", {
    label = "Правка моего модуля", category = "Модули", minAccess = "admin",
})

if GRM.Admin.Can(ply, "mymodule.edit") then ... end
```

Право автоматически появится в матрице полномочий и в CAMI.
