# GRM Documents — устойчивость хранения v2.1

## Проблема

Реестр мог продолжать считать документ выданным, когда физический бланк исчезал из инвентаря. Основная причина — слабая персистентность старого `grm_inventories.json`: повреждённый/пустой main загружался как `{}` и затем мог быть перезаписан автосейвом. Реестр документов также не имел проверенной резервной цепочки.

## Инвентарь v1.7

- ключ RP-состояния — CharacterKey;
- источники загрузки: main → interrupted temp → backup;
- каждый источник декодируется с `JSONToTable(raw, false, true)`;
- `_grm_meta.revision` определяет самый новый источник, а старые файлы без revision сравниваются по полноте записей/слотов;
- синтаксически валидный, но пустой main не побеждает наполненный backup;
- повреждённый JSON помещается в карантин;
- если все существующие источники повреждены, сохранение блокируется;
- запись: проверенный temp → main → backup;
- exact read-back и повторный decode каждого файла;
- `GRM.Inventory.SaveNow(reason)` для критичных операций;
- немедленное сохранение при смене персонажа и отключении игрока.

Файлы:

- `data/grm_inventories.json`;
- `data/grm_inventories_backup.json`;
- временный `data/grm_inventories_write_tmp.json`.

## Реестр документов v2.1

Та же схема revision/fullness и fail-closed применяется к:

- `data/grm_documents.json`;
- `data/grm_documents_backup.json`;
- `data/grm_documents_write_tmp.json`.

Повреждённый реестр не заменяется пустым. При успешной загрузке backup/temp main автоматически восстанавливается.

## Физические копии v1.2

- после `AddItem` вызывается немедленный `Inventory.SaveNow`;
- если диск не подтвердил запись, новый слот удаляется и выдача возвращает ошибку;
- копия содержит `copyID`, `ownerKey`, `docType` и `generation`;
- реестр хранит текущий `physicalGeneration`;
- после восстановления старые потерянные/украденные копии предыдущего поколения считаются аннулированными;
- `/docrestore <type>` восстанавливает один отсутствующий личный бланк;
- `/docrestore all` восстанавливает все отсутствующие личные бланки;
- cooldown — 6 часов на тип документа;
- C-меню показывает кнопку восстановления, когда реестр есть, а своего физического бланка нет;
- при входе/смене персонажа игрок получает одно уведомление о недостающих бланках.

Восстановление не создаётся, если документ аннулирован, отозван или собственный физический экземпляр уже находится в инвентаре.
