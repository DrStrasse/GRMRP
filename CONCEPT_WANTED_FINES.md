# Концепция доработки системы розыска и штрафов

**Дата:** 2026-08-12 · **Статус:** предложение к обсуждению, код не изменён
**Область:** розыск (гражданский/военный), штрафы, служебные компьютеры Жандармерии и Полиции Порядка

---

## 2. Найденные дефекты

### Блокирующие (функции не работают)

**Д1. Кнопка «В розыск» на обоих компьютерах не работает — несовпадение сигнатур.**
Компьютер вызывает `AddCharge(ply, p, {code=..., title=..., level=...})`, а функция объявлена как
`W.AddCharge(issuer, targetSid, articleId, text, forceLevel)` — третьим аргументом ждёт **строку ID статьи**.
`catalog(tostring(<таблица>))` не находит статью → `return false, "Статья каталога не найдена"`.
Игрок видит «Ориентировка передана патрульным экипажам!», в базе — ничего.
*Нужен вызов `W.AddCustomCharge`.*

**Д2. У компьютера жандармерии нет серверного обработчика.**
`init.lua` регистрирует `GRM_CompMilPolice_Act`, но `net.Receive` для него отсутствует.
Клиент жандармерии шлёт команды в **полицейский** канал `GRM_CompPolice_WantedAct` — то есть военный розыск
физически идёт через полицейский терминал и, попутно, наследует дефект Д1.

**Д3. Вкладка «База штрафов» ничего не показывает.**
Ни на одном из компьютеров нет чтения базы штрафов. Кнопка выполняет
`LocalPlayer():ConCommand("say /fine ...")` — эмуляция чата от игрока. Последствия: сумма ограничена парсером
чата, штраф уходит в общий чат, история не ведётся, цель ищется по подстроке ника.

**Д4. HUD всегда показывает «РОЗЫСК: НЕТ».**
`cl_grm_augmentations_hud.lua:289` читает `GetNWBool("GRM_Wanted")`, а сервер выставляет
`SetNW2Int("GRM_WantedLevel")`. Разные ключи — индикатор мёртв.

### Дыры в безопасности

**Д5. `net.Receive("GRM_CompPolice_WantedAct")` не проверяет права.**
Проверка `CanManage` есть только в `ENT:Use`. Само нет-сообщение принимается от любого клиента, без проверки
фракции, без проверки дистанции до терминала, без rate-limit. Любой игрок может объявить в розыск или снять
с розыска кого угодно. Единственный барьер — `W.CanEdit` внутри `AddCharge`, но он проверяет **другую**
систему прав (см. Д7), а из-за Д1 до него дело и не доходит.

**Д6. Утечка базы данных клиенту.**
`ENT:Use` шлёт `net.WriteTable` целиком: `Documents.Registry` (все документы всех игроков),
`Wanted.Records` (вся база розыска), `Documents.Templates`. Это и утечка персональных данных, и риск
превысить лимит нет-сообщения (64 КБ) на населённом сервере — тогда терминал просто перестанет открываться.

### Архитектурные

**Д7. Три независимых источника прав.**
1. `W.CanEdit/CanView` → `AccessManager` → `data/grm_wanted/access.json` (фракция/роль/отдел/SteamID);
2. `ENT:CanManage` → поиск подстрок `ordnung`/`polizei`/`полиц`/`жандарм`/`военн` в названии фракции + `Documents.Templates.access.badges`;
3. `E.CanFine` → `finePerms` фракции в экономике.

Настроив доступ в `/wanted_access`, админ не получает доступ к терминалу, и наоборот. Эвристика по подстроке
даёт доступ любой фракции, в названии которой встретилось «военн».

**Д8. Нет разделения юрисдикций.** `W.Records` — плоская таблица, у записи нет поля органа/типа розыска.
Вкладка «Военный розыск» показывает тех же людей, что и полицейская: обе итерируют по всей базе. Жандармерия
видит гражданские дела, полиция — военные.

**Д9. Штраф из каталога — декоративный.** У статьи есть `fine` (500–25000), но `sv_grm_wanted.lua` не содержит
ни одного обращения к экономике. Вменение статьи «Грабёж, штраф 15000» не списывает ничего.

**Д10. Розыск не снимается после отсидки.** `A.ArrestPlayer` требует `wanted > 0`, но при освобождении
уровень остаётся. Отсидевший арестовывается повторно бесконечно.

**Д11. Только онлайн-цели.** И поиск цели на сервере, и выпадающий список на клиенте работают лишь по
`player.GetAll()`. Заочно объявить в розыск нельзя — хотя БД хранит записи по `CharacterKey` и это поддерживает.

**Д12. Хардкод.** Код статьи всегда `"УК-ПП"`, даже в терминале жандармерии. Каталог из 10 статей в UI
компьютеров не используется вообще — только поле ручного ввода.

**Д13. Флаги электроники не работают.** `allowFines`/`allowArrest` в `sh_grm_electronics.lua` управляют лишь
модулем-заглушкой, который отдаёт список ников с уровнем розыска. Терминалы их не учитывают.

## 3. Предлагаемое решение

### 3.1. Юрисдикции (решает Д8, Д12)

Добавить в запись поле `jurisdiction`: `"civil"` | `"military"`, в статью каталога — то же.
Правило видимости: полиция видит `civil`, жандармерия — `military`, прокуратура/суперадмин — всё.
Военнослужащий, совершивший бытовое преступление, попадает в гражданскую базу; дезертир — в военную.

Расширить каталог военными статьями: СОЧ, дезертирство, неисполнение приказа, утрата оружия,
нарушение караульной службы, мародёрство. Добавить в UI обоих терминалов выбор статьи из каталога
(с автоподстановкой штрафа и уровня) — при сохранении поля ручного ввода.

### 3.2. Единые права (решает Д5, Д7)

`AccessManager` — единственный источник истины. `ENT:CanManage` переводится на
`W.CanView`/`W.CanEdit` + проверку юрисдикции терминала. Эвристику по подстрокам оставить только как
фолбэк на случай пустого `access.json`, чтобы не сломать текущие сервера.

В `net.Receive` добавить: повторную проверку `CanEdit`, проверку `IsValid(ent)` и дистанции (≤300 юнитов,
как в электронике), rate-limit 0.5 с, клампы длин строк.

### 3.3. Связка розыска и штрафов (решает Д3, Д9)

Ввести реестр штрафов `data/grm_wanted/fines.json`: `{id, target, issuer, amount, reason, article,
jurisdiction, status: "unpaid"|"paid"|"cancelled", issued, paid}`.

При вменении статьи с `fine > 0` — автоматически создавать **неоплаченный** штраф (не списывать молча).
Оплата — командой или в терминале; при оплате деньги проходят через `E.Fine`, сохраняя логику долей
фракция/государство. Вкладка «База штрафов» показывает реальный реестр с фильтрами и кнопками
«Оплатить»/«Аннулировать».

Открытый вопрос: списывать штраф сразу (жёстко) или копить долг (мягко). Рекомендую долг — он даёт
рычаг для отыгрыша и не обнуляет игрока при оффлайн-штрафе.

### 3.4. Связка с арестом (решает Д10)

Хук на освобождение: гасить уровень розыска по статьям, за которые отсидел, оставляя запись в истории.
Опционально — «отработка» неоплаченных штрафов сроком.

### 3.5. Заочный розыск (решает Д11)

Резолв цели по `CharacterKey` через существующий `GRM.Identity.ResolveCharacter` и реестр документов,
а не только по `player.GetAll()`. В UI — поиск по ФИО/номеру паспорта с автодополнением.

### 3.6. Сеть и приватность (решает Д6)

Заменить дамп таблиц на постраничную выдачу: терминал запрашивает страницу (20–50 записей) с фильтром,
сервер отдаёт только нужные поля и только своей юрисдикции. `Documents.Registry` целиком не слать никогда.

### 3.7. Мелочи (Д4, Д13)

Синхронизировать `GRM_Wanted`/`GRM_WantedLevel`. Учитывать `allowFines`/`allowArrest` в терминалах.

## 4. Порядок работ

| Этап | Содержание | Риск |
|---|---|---|
| 1 | Д1, Д2, Д4 — починить сломанное | низкий |
| 2 | Д5, Д6 — безопасность и сеть | низкий |
| 3 | Д7 — единые права (фолбэк на старую эвристику) | средний |
| 4 | Д8, Д12 — юрисдикции + военный каталог | средний |
| 5 | Д3, Д9 — реестр штрафов | высокий |
| 6 | Д10, Д11, Д13 — арест, заочный розыск, флаги | средний |

Этапы 1–2 дают работающие терминалы и закрывают дыру — их можно делать сразу.
Этапы 3–6 меняют модель данных и требуют миграции `database.json` (добавление `jurisdiction`
существующим записям со значением `civil` по умолчанию).

## 5. Вопросы к обсуждению

1. **Объём.** Делать всё (1–6) или ограничиться починкой и безопасностью (1–2)?
2. **Штрафы.** Долг с оплатой или мгновенное списание?
3. **Юрисдикции.** Достаточно `civil`/`military`, или нужна третья ветка (СБ/прокуратура)?
4. **Военный каталог.** Составить статьи самому по немецкой военной тематике или дадите свой список?
5. **Совместимость.** Есть ли живой сервер с накопленной `database.json`, которую нельзя ломать?
6. **UI.** Переводить терминалы на общую тему `GRM.UI.Theme` или сохранить их палитры (синяя/зелёная)?
