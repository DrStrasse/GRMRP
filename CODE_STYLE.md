# CODE_STYLE — правила кода GRM

Короткий свод того, как пишется и проверяется код сборки. Правила не
вкусовые: каждое выросло из бага, который уже ловили на живом сервере.

---

## 1. Оформление

| Правило | Значение |
|---|---|
| Отступ | 4 пробела, табов в отступе нет |
| Хвостовые пробелы | нет |
| Конец файла | ровно один перевод строки |
| Переводы строк | LF, без BOM |

Проверка и автоправка:

```
python3 tools/lua_style.py --check   # отчёт, код возврата 1 при находках
python3 tools/lua_style.py --fix     # исправить на месте
```

**Что инструмент не трогает:**

* `lua/easychat/` и подобный сторонний код — он сверяется с апстримом,
  переформатирование ломает сравнение;
* содержимое длинных литералов `[[ ... ]]` — там пробелы это данные,
  которые видит игрок (подсказки, рамки, шаблоны писем), а не оформление.

---

## 2. Пространство имён

В Lua забытый `local` — не ошибка, и это главный источник тихих багов.

**Присвоение без `local`** пишет в общее пространство имён сервера. Наш
модуль и чужой аддон с переменной `ui` затирают друг друга; ломается
позже и в другом месте.

**Чтение имени выше его `local`-объявления** компилируется как обращение
к глобалу. Файл грузится без ошибок, падает при вызове:

```
attempt to call global 'vehicleBase' (a nil value)
```

Правила:

* всё приватное — `local`;
* если функции зовут друг друга вперемешку, ставим форвард-декларацию
  (`local f` выше, `f = function(...)` ниже), а не `function f(...)`;
* публичное складываем в таблицу модуля (`GRM.Что-то.Функция`), а не в
  голый глобал;
* если имя всё же обязано быть глобальным (его зовут другие файлы по
  имени) — вносим в белый список стенда с пояснением.

Проверка: `tools/luatest/sim_global_hygiene.lua`. Он разбирает **байткод**
(`luajit -bl`), а не текст: видит реальное решение компилятора — `GSET`
(запись в глобал) и `GGET` (чтение). Текстовый поиск здесь врёт из-за
комментариев, строк и одноимённых полей таблиц.

## 3. Обработчики: один владелец на одно имя

`net.Receive("X", f)` не добавляет обработчик, а **заменяет** предыдущий.
То же с `hook.Add(событие, имя, f)` при совпадении имени. Если два наших
файла принимают одно сообщение в одном realm, работает ровно один — и
какой именно, решает алфавитный порядок загрузки `autorun`. Переименовал
файл — поведение сервера изменилось само.

Допустимо:

* одно имя в SERVER-файле и в CLIENT-файле — это разные машины;
* осознанная замена: `hook.Remove(...)` тем же именем **прямо перед**
  `hook.Add(...)` (так `zz_grm_bleedout` заменяет обработчик урона 911);
* защита флагом: `if not GRM._tabBalRcv then ... end` (валюта, еда).

Недопустимо: два «просто так» обработчика и надежда, что сработают оба.

Проверка: `tools/luatest/sim_net_hook_conflicts.lua`.

## 4. Комментарии

Комментарий объясняет **ПОЧЕМУ**, а не пересказывает код. По-русски.

Плохо:

```lua
-- прибавляем единицу
count = count + 1
```

Хорошо:

```lua
--[[ Личность машины считаем ЗАРАНЕЕ, а не внутри `if rec`: vehID нужен
     ниже двум блокам за пределами этого if. Пока объявление было внутри,
     снаружи читался глобал nil и связь «машина ↔ номер» терялась. ]]
```

Ценность такого текста в том, что он удерживает от «упрощения», которое
вернёт баг.

## 5. Порядок работы над правкой

1. Правка в `lua/`.
2. Синтаксис: загрузить каждый файл через `loadfile`.
3. Стенд на изменение — обязателен, в `tools/luatest/sim_*.lua`.
   Стенд должен **воспроизводить баг до фикса**.
4. **Проверить стенд откатом фикса**: вернуть баг и убедиться, что стенд
   краснеет. Стенд, который не краснеет, ничего не проверяет.
5. Полный прогон стендов: результат не должен ухудшиться ни в одном.
6. `python3 tools/lua_style.py --check`.
7. `python3 tools/build_dist.py`.
8. Коммит и push.

### Ловушки стендов (наступали многократно)

* `find("Q.WrapText")` совпадает с `Q.WrapTextOff` — искать по точной
  сигнатуре с открывающей скобкой.
* Поиск по всему файлу вместо тела нужной функции пропускает откат:
  шаблон совпадает с комментарием к правке или похожей строкой в другом
  месте. Сначала вырезать нужную функцию, потом искать внутри.
* Комментарий к фиксу сам содержит имя функции — проверка цепляется за
  него и врёт. Отсекать комментарии перед разбором.
* Кириллица: `sub(1, 5)` режет байты (в UTF-8 «КВЕСТ» это 10 байт), а
  класс `%w` не знает кириллицу.
* Стенд, падающий на `nil` после первой потери, маскирует остальные
  провалы — делать устойчивым.
* Молчаливый зелёный отчёт хуже отсутствия стенда: если стенд зависит от
  внешнего инструмента, проверять доступность инструмента явно.

---

## 6. Запуск стендов

```
luajit tools/luatest/sim_boot.lua          # один стенд
for f in tools/luatest/sim_*.lua; do luajit "$f"; done
```

Стенду `sim_global_hygiene` нужен листинг байткода: рядом с бинарником
luajit должен лежать каталог `jit/`. Путь определяется автоматически,
переопределяется переменной `LUAJIT`.
