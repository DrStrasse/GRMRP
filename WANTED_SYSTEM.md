# Система розыска, штрафов и межведомственного взаимодействия GRM

Версия документа: фаза 3 (12.08.2026). Описывает всё, что относится
к розыску, штрафам, ориентировкам, обмену сведениями между структурами
и работе спецслужб.

---

## 1. Структуры и юрисдикции

| Код | Структура | Что ведёт |
|---|---|---|
| `civil` | **Полиция Порядка** (Ordnungspolizei) | гражданские дела |
| `military` | **Полевая жандармерия** (Feldgendarmerie) | воинские дела |
| `all` | **Спецслужбы** (Гестапо, Комитет) | всё без ограничений |

Принадлежность персонажа определяется фракцией:

1. явный список `W.Config.MilitaryFactions["Имя фракции"] = true/false`;
2. эвристика по подстроке в названии (`W.Config.MilitaryPatterns`);
3. по умолчанию — `civil`.

Право сотрудника вести дела юрисдикции: `GRM.Wanted.CanUseJurisdiction(ply, j)`.
Приоритет — суперадмин → назначение в `access.json` (`all|civil|military`) →
собственная фракция.

**Общий список розыска** есть у обеих структур: и терминал, и лист розыска
показывают записи обеих юрисдикций, но у каждой строки явно проставлен
статус разыскиваемого — `ГРАЖДАНСКИЙ` или `ВОЕННЫЙ`. Чужие дела доступны
только на чтение, пока их не передали (см. раздел 4).

## 2. Лист розыска — быстрый просмотр без компьютера

Модуль: `lua/autorun/sh_grm_wanted_board.lua` (`GRM.Wanted.Board`).

**Команды:** `/board`, `!board`, `/лист`, `/листрозыска`, `/wanted_board`;
консоль — `grm_wanted_board`, `grm_wantedlist`.

Окно (единая XUI-тема GRM):

* фильтры **Все / Гражданские / Военные**;
* поиск по имени, ключу персонажа и статье;
* по каждой записи: уровень розыска, статус (гражд./воен.), две последние
  статьи, общее число статей, неоплаченный долг, признак «в сети»,
  время обновления;
* кнопки **`/fr` своим**, **`/dep` по волне** (только при праве на
  редактирование) и **Копировать ключ** — доступны всем читателям;
* строка состояния: сколько показано, сколько гражданских и военных.

Лист **только читает**: изменить, снять или завести дело отсюда нельзя.
Записи, скрытые спецслужбой, в лист не попадают через терминалы и в эфир.

Права на чтение: `access.json` → фолбэк по названию фракции (та же
эвристика, что у терминалов) → агенты спецслужбы всегда.

Ограничения: не более 200 записей в пакете, запрос не чаще раза в секунду.

## 3. Ориентировки по служебным каналам

Модуль: `lua/autorun/sh_grm_wanted_bulletins.lua` (`GRM.Wanted.Bulletins`).

| Канал | Кто слышит |
|---|---|
| `fr` | своя фракция (волна ведомства) |
| `dep` | все фракции с включённым `DepAccess` — межведомственная волна `/dep`, `/d` |

Получатели считаются по тем же правилам, что и в `sh_factions.lua`,
поэтому эфир слышат ровно те же люди, что и обычные `/fr` и `/dep`.

### Ручные команды

| Команда | Действие |
|---|---|
| `/fr_wanted Игрок [примечание]` | ориентировка по записи розыска своим |
| `/dep_wanted Игрок [примечание]` | то же соседним ведомствам по волне |
| `/bulletin fr\|dep Текст` | свободная ориентировка без привязки к делу |

Синонимы: `/frw`, `/ориентировка`, `/depw`, `/dw`, `/orient`.
Консоль: `grm_bulletin_fr`, `grm_bulletin_dep`, `grm_bulletin`.

### Автоориентировки

| Событие | Что уходит |
|---|---|
| новая статья (`GRM_WantedChargeAdded`) | сводка своим по `/fr` |
| уровень ≥ `AutoDepLevel` (по умолчанию 3) | сводка на волну `/dep` |
| снятие розыска (`GRM_WantedLevelChanged` → 0) | «ОТБОЙ ОРИЕНТИРОВКИ» на волну |
| штраф ≥ `AutoFineAmount` (25 000) | уведомление о взыскании на волну |

Текст ориентировки: имя, **статус (ГРАЖДАНСКИЙ / ВОЕННЫЙ)**, уровень и его
название, до трёх последних статей, отметка «фигурант в сети», примечание.

Защита от спама: одна автоориентировка на цель не чаще чем раз в 20 секунд,
ручная — не чаще чем раз в 3 секунды на сотрудника.

## 4. Передача сведений между структурами

Модуль: `lua/autorun/sh_grm_wanted_exchange.lua` (`GRM.Wanted.Exchange`).
Данные: `data/grm_wanted/exchange.json` (`version = 1`).

Три операции:

| Операция | Что происходит |
|---|---|
| **TRANSFER** | юрисдикция дела меняется (`civil ↔ military`); статьи переводятся вместе с делом; прежний хозяин сохраняет доступ через `shared`; в деле остаётся отметка в `transfers`. Обратная передача выполняется тем же способом. |
| **SHARE** | дело остаётся у хозяина, соседняя структура получает копию сведений (`record.shared[jur] = true`). Отзывается через `Unshare`. |
| **REQUEST** | заявка соседям: «передайте дело» либо «дайте копию». Ложится в очередь, решение принимает структура, которая ведёт дело. |

### Команды

| Команда | Действие |
|---|---|
| `/case_transfer Игрок [примечание]` | передать дело соседям |
| `/case_share Игрок [примечание]` | поделиться копией сведений |
| `/case_request Игрок [transfer\|share] [примечание]` | подать заявку |
| `/case_requests` | открытые заявки к моей структуре |
| `/case_accept Номер [примечание]` | удовлетворить заявку |
| `/case_decline Номер [причина]` | отклонить заявку |
| `/case_cancel Номер` | отозвать свою заявку |

Консольные аналоги: `grm_case_transfer`, `grm_case_share`, `grm_case_request`,
`grm_case_requests`, `grm_case_accept`, `grm_case_decline`, `grm_case_cancel`.

В терминалах обеих структур появилась вкладка **«Обмен сведениями»** с теми же
операциями кнопками: слева — дела в производстве и кнопки передачи и
ориентировок, справа — входящие заявки с кнопками «Удовлетворить» / «Отклонить».

Каждая операция дублируется сообщением на волну департаментов и пишется
в журнал обмена (до 400 записей).

## 5. Спецслужбы: Гестапо и Комитет

Модуль: `lua/autorun/sh_grm_special_service.lua` (`GRM.SpecialService`).
Данные: `data/grm_wanted/special.json` (`version = 1`).

### Кто считается агентом

1. запись в реестре: фракция, отдел, должность или персональный ключ;
2. фолбэк по названию фракции (`gestapo`, `гестапо`, `комитет`, `abwehr`,
   `контрразвед`, `спецслужб`, `тайная полиция` и т. п.);
3. суперадмин.

Настройка реестра из консоли суперадмина:

```
grm_spec_agents faction "Gestapo" 1
grm_spec_agents steam  76561198000000012 1
```

### Полный контроль баз

Агент видит обе юрисдикции: `CanUseJurisdiction`, `CanView` и `CanEdit`
для него всегда истинны (патч накатывается после менеджера доступов).

Оперативный терминал `/spec` — пять вкладок:

* **Розыск** — все дела обеих структур; кнопки «Ур. 0», «Ур. −1»,
  «Скрыть / Раскрыть», «Изъять дело», «Копировать ключ»;
* **Штрафы** — весь реестр, кнопка «Изъять из реестра»;
* **Аресты** — арестованные сейчас, кнопка «Освободить тайно»;
* **Прикрытие** — документы прикрытия (см. ниже);
* **Журнал** — закрытый журнал спецслужбы.

### Тайные операции

| Команда | Действие |
|---|---|
| `/covert_level Игрок 0-5 [примечание]` | изменить уровень розыска |
| `/covert_wipe Игрок [примечание]` | изъять дело из базы целиком |
| `/covert_hide Игрок` / `/covert_unhide Игрок` | скрыть дело от ведомств / вернуть |
| `/covert_fine_wipe Номер [примечание]` | изъять штраф из реестра |

Все они:

* **не** пишут в обычную историю розыска (`W.History`);
* **не** порождают ориентировок и уведомлений цели;
* пишутся в **закрытый журнал**, видимый только агентам и суперадмину.

Скрытое дело (`record.covert = true`) пропадает из терминалов Полиции
Порядка и Жандармерии, из листа розыска и из эфира — но остаётся в базе
и виден спецслужбе.

### Документы прикрытия

До пяти легенд на персонажа (`SS.Config.MaxCovers`), одна активна.

| Команда | Действие |
|---|---|
| `/covers [Игрок]` | список легенд |
| `/cover_new Имя` | оформить новую легенду |
| `/cover_use Номер` | сделать легенду активной (`0` — настоящий документ) |
| `/cover_drop Номер` | аннулировать легенду |

Активная легенда кладётся в `DOC.Registry.coverBadges[charKey]`, поэтому
существующий показ документов («предъявить удостоверение») работает без
изменений: собеседник видит легенду, а не настоящую корочку.

Совместимость: если у персонажа уже был документ прикрытия старого
образца, при первом обращении он импортируется как «Легенда №1».

## 6. Форматы данных и миграция

| Файл | Версия | Что хранит |
|---|---|---|
| `grm_wanted/database.json` | **4** | дела: `sid, name, level, reasons[], jurisdiction, updated` + новые `shared`, `transfers`, `covert` |
| `grm_wanted/catalog.json` | 3 | каталог статей с юрисдикцией |
| `grm_wanted/fines.json` | 1 | реестр штрафов |
| `grm_wanted/access.json` | — | доступы и юрисдикции |
| `grm_wanted/exchange.json` | 1 | заявки и журнал обмена |
| `grm_wanted/special.json` | 1 | реестр агентов, закрытый журнал, легенды |

### Миграция v3 → v4

Выполняется автоматически при загрузке и **без потери данных**:

* поля `shared`, `transfers`, `covert` в старых базах отсутствуют — они
  просто не создаются, пока не понадобятся;
* записи без `jurisdiction` по-прежнему получают `civil` (миграция v2 → v3);
* при первой загрузке базы версии ниже 4 файл пересохраняется в новом
  формате с сообщением в консоль;
* повреждённый файл не затирается: рядом появляется
  `database.json.corrupt.<timestamp>`. То же правило действует для
  `exchange.json` и `special.json`.

Новые файлы (`exchange.json`, `special.json`) на существующем сервере
создаются пустыми при первом запуске — ничего доливать вручную не нужно.

## 7. Сетевой протокол

### Терминалы (v1.2)

`GRM_CompPolice_Open` / `GRM_CompMilPolice_Open`:

```
Entity ent, Table online, Table templates, Table registry,
Table wantedRecs, String faction, Bool isSuperAdmin,
String jurisdiction, Bool canEdit, Table fines, Table catalog,
Table requests        ← добавлено в v1.2
```

`GRM_CompTerminal_Act` (клиент → сервер):
`String action, String jurisdiction, String target, String text, UInt32 num, String extra`

Действия: `wanted_add`, `wanted_clear`, `fine_issue`, `fine_cancel`,
`bulletin_fr`, `bulletin_dep`, `case_transfer`, `case_share`,
`case_request`, `case_accept`, `case_decline`, `refresh`.

`GRM_CompTerminal_Fines` (сервер → клиент): `Table wanted, Table fines, Table requests`.

Все кнопки терминалов ходят через единую клиентскую обёртку
`GRM_CompTerminal_Send(action, target, text, num, extra)`.

### Новые каналы

| Канал | Направление | Полезная нагрузка |
|---|---|---|
| `GRM_WantedBoard_Req` | клиент → сервер | `Bool wantHistory` |
| `GRM_WantedBoard_Data` | сервер → клиент | `Bool canEdit, String myJur, Table rows` |
| `GRM_WantedBulletin_Send` | клиент → сервер | `String channel, String targetKey, String note` |
| `GRM_WantedBulletin_Msg` | сервер → клиент | `UInt8 r,g,b, String prefix, String text` |
| `GRM_SpecService_Open` | клиент → сервер | — |
| `GRM_SpecService_Data` | сервер → клиент | `Table wanted, fines, arrests, journal, online, covers` |
| `GRM_SpecService_Act` | клиент → сервер | `String act, String target, String text, Int32 num` |
| `GRM_SpecService_Result` | сервер → клиент | `Bool ok, String msg` |

## 9. Тесты

```
luajit tools/luatest/sim_wanted_phase3.lua      # лист, ориентировки, обмен, спецслужбы
luajit tools/luatest/sim_wanted_migration.lua   # миграция базы и каталога
luajit tools/luatest/sim_wanted_v2.lua          # ядро розыска
luajit tools/luatest/sim_arrest.lua             # аресты
luajit tools/luatest/roundtrip_test.lua         # сквозной прогон экономики
```

`sim_wanted_phase3.lua` покрывает 15 групп: юрисдикции, сохранение новых
полей и миграцию v3 → v4, сбор листа, права на каналы, тексты и получателей
ориентировок, автоориентировки по хукам, передачу и возврат дела, копии
сведений, заявки и решения по ним, персист обмена, опознание агентов,
все тайные операции, документы прикрытия, персист спецслужбы, изъятие
штрафа и устойчивость к повреждённым файлам и несуществующим целям.

## 10. Сборка

```
python3 tools/build_dist.py
```

Собирает четыре архива в `dist/`. Модули фазы 3 входят и в полный аддон,
и в экономический срез `grm_economy.zip` (там же — терминалы, документы
и ядро розыска).
