# GRM Factions — регистрационное и публичное имя

## Контракт

Каждая фракция имеет два независимых имени:

1. **Регистрационное имя** — ключ таблицы `Factions[registrationName]`.
   Оно используется только системой: persistence, capability/access maps,
   бюджеты, документы, транспорт, двери, службы, CharacterKey membership и
   межмодульные ссылки.
2. **Публичное имя** — поле `Factions[registrationName].DisplayName`.
   Оно показывается игрокам: государственные новости, волна департамента, TAB,
   меню персонажа, списки состава/лидеров, таблички служебных диспетчеров и
   заголовки пользовательского UI.

Публичное имя нельзя использовать как ключ persistence. Две фракции технически
могут получить одинаковый DisplayName, поэтому обратное разрешение публичного
имени возвращает nil при неоднозначности.

## Совместимость и миграция

Существующие ключи `Factions` не переименовываются. При загрузке старой записи
без `DisplayName` значение один раз мигрирует из текущего регистрационного имени
и сохраняется в `data/factions.json`. Поэтому старые доступы и интеграции
продолжают работать без смены формата ключей.

Старое действие `createFaction(name, leader)` сохранено: для него DisplayName
равен регистрационному имени. Новый UI использует `createFactionV2` и требует
оба поля.

## API

```lua
GRM.Factions.DisplayName(registrationName)
GRM.Factions.RegistrationName(factionTable)
GRM.Factions.PlayerDisplayName(ply)

FactionsAPI.GetDisplayName(registrationName)
FactionsAPI.GetRegistrationName(value)
FactionsAPI.SetDisplayName(registrationName, publicName)
```

NW-контракт игрока:

- `GRM_Faction` / `Faction` — регистрационное имя, не менять;
- `GRM_FactionDisplay` — публичное имя;
- `GRM_FactionTag` — короткий радиотег, отдельный от обоих имён.

## Первая интеграционная волна

На DisplayName переведены:

- `/dep` и `/depb`;
- `/gnews`;
- TAB;
- меню выбора персонажа;
- `/members`, `/leaders`;
- 3D2D служебного диспетчера;
- главный список фракций в админ-меню;
- селекторы служебного диспетчера.

Административные матрицы доступов продолжают показывать/хранить регистрационные
ключи, пока соответствующий UI не получит безопасную пару `label + data`.

## Приглашения v2

Приглашение привязано к CharacterKey и содержит:

- уникальный `inviteID`;
- регистрационный ключ и публичное имя фракции;
- CharacterKey/имя пригласившего;
- обещанную стартовую должность и отдел;
- время создания и истечения (5 минут).

Сервер проверяет роль, отдел, занятость персонажа, право лидера, срок и nonce.
Старые записи `{ faction, from, time }` читаются и получают legacy-ID. Игроку
приходит singleton-окно с публичным названием, системным ключом, назначением,
таймером и кнопками принятия/отказа. При смене персонажа окно закрывается или
заменяется приглашением нового CharacterKey. `/fjoin` и `/fdecline` сохранены
как fallback. Все решения записываются в `GRM.Audit`.

## Названия отделов

Для отделов применяется тот же принцип без миграции системных связей:
`Departments` содержит стабильные ключи, а `DepartmentDisplayNames[key]` —
публичную подпись. Кнопка переименования меняет только подпись. Участники,
модели, оружие, spawn points и access matrices продолжают использовать прежний
ключ. Детали и кадровая система описаны в `CONCEPT_FACTION_CORE_V4.md`.
