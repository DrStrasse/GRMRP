# CONCEPT: Гаражи GRM (v1.0.0, 19.08.2026)

Заказ владельца: «модуль гаража и стыковка с дилером. Гараж личный уже есть,
но не хватает инструмента создания зоны гаражей и точек спавна транспорта.
Нужно продумать полноценную механику: точки спавна, направление купленного
транспорта в личный гараж, вызов меню гаража, спавн из гаража, тулы/энтити.
Не забываем про порядок, иерархию, дефрагментацию кода и выполнение по частям».

## 1. Что было и почему этого мало

* «Гараж» существовал только как **список записей** внутри дилера
  (`VD.Garages[CharacterKey][id]`). Физического места у него не было.
* Выдача и уборка машины были возможны **только у NPC-дилера**: подошёл,
  открыл меню, машина появилась на площадке дилера.
* Логика выдачи/уборки была раскопирована по операциям меню дилера
  (`buy` / `retrieve` / `store` / `sell` / `remove`) — четыре почти одинаковых
  куска с разными проверками.

## 2. Слои и иерархия (что от чего зависит)

```
GRM.Boot ──► GRM.Garage (ядро: данные, зоны, места, правила)
                 │  hook GRM_VehicleDealerSpawned      (дилер → гараж)
                 │  VD.IssueRecord / VD.StoreRecord    (гараж → дилер)
                 ▼
        GRM.VehicleDealer (спавн машин, реестр активного транспорта)
```

Правила зависимостей:

1. **Ядро гаражей не знает про UI и тулы** — только данные и правила.
2. **Спавн и уборка машины — исключительно у дилера.** Гараж вызывает
   `VD.IssueRecord(ply, recordID, place)` и `VD.StoreRecord(ply, recordID)`.
   Это же используют операции меню дилера — одна реализация на сборку.
3. **Дилер про гаражи ничего не знает.** Привязка покупки идёт хуком
   `GRM_VehicleDealerSpawned`; единственная обратная точка — необязательный
   вопрос `GRM.Garage.DealerIssueBlocked` (строгий режим).
4. Загрузка по частям через планировщик: `GRM.Boot.OnMapStart`
   `normal` — данные, `late` — стойки (не толкаемся с перм-пропами в один тик).

## 3. Модель данных

`data/grm_garage/<карта>.json`

```
гараж = {
  id, name,
  kind    = public | faction | private,
  faction, owner,          -- для ведомственного / личного
  fee,                     -- плата за выезд (0 = бесплатно)
  zone    = { min, max },  -- AABB: дёшево и предсказуемо
  slots   = [ { id, name, pos, ang, lift } ],
  terminals = [ { id, pos, ang } ],
  linkedDealers = [ dealerID ]
}
```

Запись машины (живёт у дилера) получила поле `garageID` — «домашний гараж».

Ограничения: `MinZone = 200`, `MaxSlots = 24`, `MaxGarages = 64`,
`SlotRadius = 150` (радиус проверки занятости места), `UseDistance = 220`
(дальность стойки).

## 4. Механика

### 4.1 Разметка (тул «GRM: гаражи», суперадмин)

1. Режим **«Зона гаража»** — два клика ЛКМ по земле = AABB зоны, гараж
   создаётся и становится выбранным.
2. Режим **«Место стоянки»** — ЛКМ внутри зоны: позиция + направление
   (по взгляду или по сторонам света) + высота выдачи.
3. Режим **«Стойка вызова»** — ЛКМ: энтити `grm_garage_terminal`.
4. **ПКМ** по земле — выбрать гараж для правки; **ПКМ по дилеру** —
   привязать/отвязать его к выбранному гаражу.
5. **R** — удалить ближайшее место/стойку; **Shift+R** в режиме зоны —
   удалить гараж.

Всё видно в мире: зона — рамкой (выбранная золотая), места — габаритной
коробкой машины со стрелкой направления (зелёная свободна, красная занята),
стойки — маленькой рамкой.

### 4.2 Игрок

* Вызов меню: `/garage` (`/гараж`) внутри зоны **или** `E` на стойке.
  Вне гаража команда, как и раньше, отдаётся дилеру — конфликта нет.
* В меню: список личного транспорта (в гараже / на карте + расстояние),
  домашний гараж каждой машины, состояние всех мест стоянки.
* Кнопки: **ВЫДАТЬ** (на первое свободное место, с оплатой выезда),
  **УБРАТЬ В ГАРАЖ** (машину нужно загнать в зону), **ПРИПИСАТЬ СЮДА**.
* В том же окне — служебная техника организации (автопарк), приписанная к
  этому гаражу: **ВЫДАТЬ СЛУЖЕБНУЮ** / **ВЕРНУТЬ В ГАРАЖ** идут через тот
  же единый диспетчер `GRM.Vehicles`. Убрать в гараж можно и личную, и
  фракционную машину.
* Машину из чужого гаража здесь не выдадут — скажут, где она стоит.

### 4.3 Дилер

* Покупка личного транспорта приписывает машину к гаражу:
  привязанный к дилеру → личный гараж игрока → ближайший доступный.
  Игроку приходит уведомление «Транспорт закреплён за гаражом «…»».
* В меню дилера в карточке гаража видно домашний гараж.
* Конвар `grm_garage_strict`:
  * `0` (по умолчанию) — всё как раньше, дилер выдаёт тоже;
  * `1` — личный транспорт выдаётся ТОЛЬКО в своём гараже.

## 4.3.1 Выбор гаража при покупке (игрок)

В окне дилера, рядом с поиском, стоит выпадающий список **«Гараж: …»**:
«автоматически» (привязанный к дилеру → личный → ближайший, помечен ★) или
любой конкретный гараж, доступный игроку, с числом свободных мест. Выбор
уходит вместе с покупкой (`record.requestedGarage`), проверяется на стороне
гаражей (`G.ValidateChoice`: существует, доступен, размечены места) и, если
не подошёл, покупка не срывается — работает автоподбор с пояснением игроку.

## 4.3.2 Режим выдачи покупок — настройка дилера

В админке дилера (ПКМ тулом по NPC) есть строка **«Выдача покупок»**:

* **Выдавать у дилера** — как раньше: купил и машина стоит на площадке;
* **Отправлять в гараж** — покупка сразу ложится в гараж на хранение, у
  дилера её не выдают (кнопка называется «КУПИТЬ В ГАРАЖ»);
* **На выбор игрока** — в карточке две кнопки: «КУПИТЬ И ВЫДАТЬ» и «В ГАРАЖ».

Рядом галочка **«Показывать кнопку „ВЫДАТЬ“ из гаража»**: снимаете — у дилера
машину из гаража не достать, только в самом гараже (в карточке гаража кнопка
подписывается «ЗАБРАТЬ В ГАРАЖЕ»). Проверка стоит и на сервере, а не только в
интерфейсе. Служебный транспорт организаций всегда выдаётся на месте.

## 4.4 Ворота гаража (двери) — админ

Гараж можно соединить с конкретным набором дверей: режим тула **«Ворота
гаража»**, ЛКМ по двери — привязать/отвязать (R — тоже отвязать). Одна дверь
принадлежит только одному гаражу.

* Доступ к воротам считает сам гараж (хук `GRM_DoorAccessOverride`):
  городской — всем, ведомственный — организации, личный — владельцу.
* Смена типа гаража запирает/отпирает его ворота (`G.ApplyDoorState`).
* В меню гаража появляется одна кнопка **ОТКРЫТЬ / ЗАКРЫТЬ ВОРОТА** на весь
  набор дверей.
* Если дверь уже входит в объект недвижимости, гараж в её правила НЕ лезет —
  там свои ордера и печати (приоритет однозначный, спора двух систем нет).

## 4.5 Гараж вместе с домом — игрок

Гараж привязывается к объекту недвижимости: **ПКМ тулом по двери дома**
(объект определяется автоматически). После этого:

* игрок покупает/арендует дом → гараж становится его личным (`kind=private`,
  `owner=CharacterKey`), ворота слушают владельца;
* дом оформлен на организацию → гараж становится ведомственным;
* дом освобождён, выселен или аренда истекла → гараж возвращается к типу,
  который задал админ (`baseKind`), владелец очищается.

Недвижимость сообщает о смене владельца хуком `GRM_PropertyOwnerChanged`
(покупка, аренда, освобождение, выселение, истечение аренды) — гараж просто
подписан на него и ничего не знает про внутренности недвижимости.

## 5. Что дальше (не сделано намеренно)

* Аренда мест игроками (плата за стоянку по времени) — нужна экономика ренты.
* Ведомственные гаражи с квотами по отделам — после обкатки тегов отделов.
* Метка гаража на мини-карте — ждём решения владельца, не засорять ли карту.
