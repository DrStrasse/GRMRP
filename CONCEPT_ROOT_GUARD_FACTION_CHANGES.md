# Root Guard — защита межфракционных изменений v2

**Заказ владельца:** любой админ или суперадмин, кроме корня
`STEAM_0:1:712444114`, перед изменением ЧУЖОЙ фракции обязан получить
одобрение владельца. Без одобрения действие не исполняется.

## Граница

- Root-владелец действует сразу.
- Лидер меняет только собственную фракцию в пределах выданных прав.
- Админ/суперадмин при действии над чужой фракцией создаёт fail-closed
  заявку в `GRM.Root.Queue`; сервер не меняет данные до ответа root.
- Если root не в сети — заявка не исполняется и после рестарта пропадает.

## Защищаемые действия

1. удалить / переименовать / сменить публичное имя, тег, цвет фракции;
2. сменить лидера;
3. добавить, уволить, перевести участника; изменить роль, отдел, подотдел;
4. изменить структуру: роли, отделы, подотделы, ключи и порядок;
5. изменить фракционные доступы, сервисные права, модели, оружие, duty,
   бюджетные и транспортные разрешения;
6. назначить себя в чужую фракцию, включая лидером.

## Исполнение

Каждый защищённый action получает стабильный `kind` и нормализованный
payload. `GRM.Root.RegisterExecutor(kind, fn)` выполняет только конкретную
серверную функцию после одобрения. UI/клиент никогда не выполняет действие
самостоятельно и не шлёт повторный net-пакет после approval.

## UI root

В окне `/root_queue` показываются: кто запросил, какая фракция, точное
действие, до/после, целевой участник, время. Кнопки только «ОДОБРИТЬ» и
«ОТКЛОНИТЬ».

## Тесты

`sim_rootguard_factions.lua`:
- root проходит сразу;
- суперадмин чужую фракцию не меняет до approval;
- approval запускает один раз;
- decline не меняет данные;
- лидер своей фракции не попадает в очередь;
- очередь очищается на рестарте;
- нельзя подменить faction/action/payload клиентом.
