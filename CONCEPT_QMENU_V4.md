# Q-меню «Стройка» — переписывание с нуля (v4). Концепция

Документ описывает, **что и как будет сделано**, до написания кода.
Текущий файл `sh_grm_qmenu.lua` — 1753 строки, 50 инструментов в каталоге,
27 net-сообщений. Он не чинится точечно: три попытки фикса зависания
результата не дали.

---

## 1. Диагноз: почему чиним не патчем, а переписыванием

Зависание — **не ошибка Lua** (консоль пуста, игра не сворачивается).
Значит, кадр не завершается. Я не смог доказать конкретную строку, поэтому
меняю подход: **убираю целые классы причин**, а не отдельные строки.

Четыре подозреваемых, каждый достаточен сам по себе:

| № | Что происходит сейчас | Почему это вешает клиент |
|---|---|---|
| **A** | При открытии меню исполняется `BuildCPanel` **каждого** stool | Это **чужой код** сторонних аддонов в нашем кадре. Один цикл внутри — и клиент стоит. До задачи 13 этот блок не выполнялся **никогда** (условие было ложным), поэтому раньше и не висло |
| **B** | Каталог создаёт `SpawnIcon` на каждую плитку сразу | Рендер иконки требует загрузки модели. Десятки незакэшированных моделей = длинный стопор движка, неотличимый от зависания |
| **C** | `fitText` меряет текст в `Paint` — каждая строка каждый кадр | Десятки `GetTextSize` на кадр; на битой кодировке цикл не сходился |
| **D** | `SetTall` + ручной `PerformLayout` внутри раскладки | Раскладка заказывает саму себя |

Ключевое наблюдение, объясняющее «появилось после снятия суперадмина»:
при `adminsToo = false` **суперадмин видит ванильное Q и наш код не
исполняется вовсе**. Игрок без прав — единственный, кто вообще открывает
нашу панель. Баг не «появился» — он впервые получил исполнителя.

### Семь правил v4 (каждое закрывает класс отказов)

1. **Никакого чужого кода в нашем кадре.** `BuildCPanel` не вызывается
   никогда. Настройки инструмента строим из **описания-данных** (§6).
2. **Ничего не мерить в `Paint`.** Все размеры и обрезки — один раз при
   сборке, результат в поле панели.
3. **Раскладка одноразовая.** Только `SetPos`/`SetSize` константами.
   Ни `PerformLayout` вручную, ни `SetTall` по содержимому.
4. **Тяжёлое — порциями.** Иконки и плитки создаются по бюджету на кадр
   (§12), а не пачкой.
5. **Любой цикл — со счётчиком.** Верхняя граница итераций обязательна.
6. **Сторож кадра.** Сборка окна замеряется; превышение бюджета пишет в
   консоль имя этапа и прекращает сборку (§12).
7. **HOLD-Q как ванильное — не трогать.** Зажал Q — меню открыто, отпустил —
   закрыто. Это приказ владельца и привычка игроков. Гонку открытия/закрытия
   лечим не снятием удержания, а тем, что его ломало (§7).

## 2. Роли и доступы

Три роли, как во всём проекте:

| Роль | Что видит и может |
|---|---|
| **Игрок** | Каталог разрешённых моделей, разрешённые инструменты, свои объекты. Лимит объектов. Вкладки «Настройки» нет |
| **Лидер фракции** | То же + объекты фракции во вкладке «Мои объекты» (снятие/учёт) |
| **Суперадмин** | Всё без ограничений + вкладка «Настройки», курирование каталога, лимиты, доступ к инструментам |

Правило доступа к инструменту (порядок проверки):

```
суперадмин                        → разрешено
инструмента нет в каталоге        → запрещено
белый режим (whitelistMode)       → только из toolAllow
иначе                             → всё, кроме toolDeny
```

Права проверяются **дважды**: на клиенте (чтобы не рисовать недоступное) и
**обязательно на сервере** при спавне и в хуке `CanTool`. Клиент — только
удобство, источник истины — сервер.

## 4. Вкладки

### 4.1 Каталог (по умолчанию)
Сетка плиток разрешённых моделей. Поиск сверху (фильтр по имени).
- **ЛКМ** — заспавнить перед собой
- **ПКМ** — убрать из каталога *(только суперадмин)*

Пусто → крупная подсказка: «Каталог пуст. Суперадмин наполняет его
командой `/qm_prop_add`, глядя на объект».

### 4.2 Инструменты — справа, не вкладка
Список по категориям (`Соединения`, `Механика`, `Свет и эффекты`,
`Интерфейс`, `Оформление`, `Точность и копирование`, `Опасное`, `Прочее`)
живёт **в средней колонке** на всю высоту, как в ванильном Q.
Вкладки «Инструменты» нет: слева только Каталог / Мои объекты / ⚙.
Категории сворачиваются. Недоступные инструменты **показываются серыми** с
пояснением — игрок понимает, что существует, а не гадает.

Выбор строки: выдаёт тулган, ставит режим, и **в крайней правой колонке**
появляются параметры (§6) — только если есть ручная схема.

### 4.3 Мои объекты
Список заспавненного: модель, время, расстояние. Кнопки «Убрать» и
«Убрать все». Лидеру фракции — переключатель «Мои / Фракции».

### 4.4 Настройки ⚙ (только суперадмин)
Переключатели конфига, лимит объектов, доступ к инструментам
(белый/чёрный список), курирование каталога. Дублирует и не заменяет
`/grm_admin` — правка сразу пишется в `data/grm_qmenu.json`.

## 5. Поэтапность открытия

Окно появляется мгновенно, наполняется порциями — клиент не «пропадает»:

```
кадр 1   рамка, шапка, вкладки, подвал   (мгновенно)
кадр 2   содержимое вкладки без иконок   (текст готов)
кадр 3+  иконки порциями по бюджету      (§12)
```

Если на каком-то этапе бюджет превышен — сборка останавливается, в окне
появляется строка «Показано N из M» и кнопка «Показать ещё». **Клиент
никогда не уходит в долгий кадр.**

## 6. Настройки инструмента — данные вместо чужого кода

Это главное изменение и главная защита от зависания.

Сейчас: `BuildCPanel` чужого stool исполняется у нас → любой их цикл
вешает игру. В v4 **мы не вызываем чужой код никогда**.

Вместо этого — **описание настроек как данные**. У stool уже есть таблица
`TOOL.ClientConVar` (это данные, не код). Из неё строим контролы сами:

```lua
GRM.QMenu.Schema["grm_perm_tool"] = {
    { cvar = "grm_perm_tool_owner",  type = "choice", label = "Кому принадлежит",
      choices = { {"Серверное", "server"}, {"Фракция", "faction"} } },
    { cvar = "grm_perm_tool_freeze", type = "bool",   label = "Заморозить" },
    { cvar = "grm_perm_tool_label",  type = "text",   label = "Метка" },
}
```

Четыре типа контролов: `bool`, `choice`, `number`, `text`. Больше не нужно.
Схема пишется **нами** для наших 18 инструментов; для чужих — авто-схема
из их `ClientConVar` (тип угадывается по значению: `0/1` → bool, число →
number, иначе text).

Если схемы нет и `ClientConVar` пуст — показываем честную подсказку:
«У инструмента нет параметров в быстром меню» и кнопку **«Открыть
ванильную панель»**, которая просто открывает стандартное Q. Чужой код
исполнится в **их** окне, а не в нашем кадре.

## 7. HOLD-Q: удержание остаётся, гонка убирается

Владелец: **удержание Q не трогать ни при каком раскладе.** Поведение как
у ванильного spawnmenu и как в текущем v3.3.0:

```
+menu  pressed=true   →  OpenMenu()     (если окно уже есть — ничего)
+menu  pressed=false  →  CloseMenu()
/qm, /build, крестик  →  переключатель / явное закрытие
смерть, наручники     →  закрыть
```

`OpenMenu` **не тоггл**. Повтор нажатия при удержании игнорируется — иначе
движок шлёт `pressed=true` несколько раз и меню мигает.

Что реально давало гонку (и что мы убираем, **не** трогая HOLD-Q):

| Источник гонки в v3 | Что делаем в v4 |
|---|---|
| `Think` гасит окно, если `gui.ScreenClickerEnabled()` мигнул | Think **не закрывает** меню. Кликер при удержании Q живой; гасить по нему — ложные срабатывания |
| `GRM_QMenu_Sync` сразу зовёт `_rebuild()` | Синк только помечает stale; пересборка на следующем кадре, окно не уничтожается |
| `/qm` и отпускание Q в одном кадре | `/qm` — отдельный тоггл. Пока Q зажата, `/qm` не закрывает (флаг `_holdOpen`) |
| `CloseMenu` в середине порционной сборки | Сборка проверяет `IsValid(_frame)` на каждой порции и молча выходит |

Крестик, ESC и смерть работают всегда: они зовут `CloseMenu` и сбрасывают
`_holdOpen`. Отпускание Q после крестика — повторный `CloseMenu` по уже
пустому слоту, безвредно.

## 8. Подсказки: где и какие

Подсказка обязана быть там, где возникает вопрос:

- **Пустое состояние** — крупным текстом в центре пустой области, с точной
  командой, которая это исправит.
- **Серая строка инструмента** — при наведении поясняет *почему* закрыт:
  «закрыт чёрным списком» / «включён белый режим».
- **Отказ сервера** — тост в подвале на 3 секунды (красный), с причиной:
  «Лимит объектов 24/24», «Модель не в каталоге».
- **Правая полка без выбора** — краткая справка по управлению тулганом.
- **Вкладка «Настройки»** — под каждой группой одна строка, что она меняет
  и для кого.

## 9. Команды

### Чат (для всех)
| Команда | Действие |
|---|---|
| `/qm`, `/build` | Тоггл меню (чат). Пока Q зажата — не закрывает |
| `/qm_clearprops` | Убрать свои объекты |
| `/qm_seed` | Мебельный набор в каталог |

### Чат (суперадмин)
| Команда | Действие |
|---|---|
| `/qm_prop_add` | Добавить модель, на которую смотрю |
| `/qm_prop_addmodel <путь>` | Добавить по пути |
| `/qm_prop_del <путь>` | Убрать из каталога |
| `/qm_prop_list` | Показать каталог |

### Консоль (клиент) — диагностика
| Команда | Действие |
|---|---|
| `grm_qmenu_diag` | Кто ещё перехватывает Q (ищет «ЧУЖОЙ») |
| `grm_qmenu_safe 1` | Аварийный режим: только каталог, без полки и иконок |
| `grm_qmenu_profile 1` | Печатать время каждого этапа сборки в мс |

`grm_qmenu_safe` остаётся навсегда как страховка: если однажды что-то
снова начнёт вешать клиент, у игрока есть рабочий режим.

## 10. Сеть

Оставляем существующие net-сообщения (они рабочие) и правило: **клиент
ничего не решает**. Спавн, удаление, смена конфига — только запрос;
проверка прав, лимита и списка — на сервере.

Защита: не чаще одного спавна в 0.4 с на игрока, лимит `menuPropCap`
(по умолчанию 24), длина строки модели ограничена, путь проверяется на
`models/` и `.mdl`.

Важное: `GRM_QMenu_Sync` больше **не перестраивает окно немедленно**.
Он помечает данные устаревшими, и окно обновится на следующем кадре —
это убирает риск «синхронизация → пересборка → синхронизация».

## 11. Совместимость и миграция

Формат `data/grm_qmenu.json` **не меняется** — на сервере уже накоплены
настройки. Читаем существующие ключи как есть; недостающие добираются из
значений по умолчанию. Файл `sh_grm_admin_hub.lua` обращается к
`GRM.QMenu.Cfg`, `.Save()`, `.ToolCatalog`, `.Version` — **все четыре
имени сохраняются**, хаб править не придётся.

## 12. Защита от зависаний (техническая часть)

| Механизм | Правило |
|---|---|
| Бюджет кадра | Не более 8 иконок за кадр; остальное — в следующем |
| Сторож сборки | `SysTime()` до/после этапа; > 50 мс → в консоль имя этапа |
| Предел циклов | Любой `while` — со счётчиком и жёстким верхом |
| Ленивые иконки | `SpawnIcon` только для видимых плиток; за экраном — заглушка |
| Без чужого кода | `BuildCPanel` не вызывается (§6) |
| Без замеров в `Paint` | Обрезка подписи один раз при сборке |
| Аварийный режим | `grm_qmenu_safe 1` отключает полку и иконки |
| HOLD-Q без гонки | Think не закрывает; синк не уничтожает окно; `_holdOpen` (§7) |

## 13. Объём и тесты

Ожидаемый размер: **~900 строк вместо 1753** за счёт отказа от
трёхколоночной раскладки, ручной геометрии и обвязки вокруг чужого кода.

Тесты (стенды LuaJIT, как в проекте):
- `sim_qmenu_v4_access.lua` — матрица прав: игрок / лидер / суперадмин
- `sim_qmenu_v4_schema.lua` — построение схемы из `ClientConVar`, включая
  мусорные значения
- `sim_qmenu_v4_budget.lua` — сборка укладывается в бюджет, порции работают
- `sim_qmenu_v4_hold.lua` — press открывает, release закрывает, повтор press
  при живом окне игнорируется, `/qm` во время удержания не гасит
- существующие `sim_qmenu*.lua` — остаются как регрессия протокола

## 14. Этапы

1. Каркас окна, вкладки, подвал, права, **HOLD-Q** (без иконок)
2. Каталог + ленивые иконки + порции
3. Инструменты + схема настроек
4. Мои объекты
5. Вкладка настроек суперадмина
6. Диагностика, аварийный режим, тесты, сборка `dist/`

После каждого этапа — коммит, пуш и ссылки на архивы.
