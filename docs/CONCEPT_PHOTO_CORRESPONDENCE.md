# Фото, новости, миникарты — разбор паков и GRM

Референс: `SYSTEMS MINIMAPS AND NEWS.zip` (не копировать в `lua/`).

## Миникарты (три разных подхода)

### 1. Navmesh 3D (`3dminimap.lua`)
- Сервер режет `navmesh.GetAllNavAreas()` в прямоугольники (центр, размер, z, 4 угла, flat).
- Мелкие полигоны отсекаются (`sv_minimap_minareasize`).
- Клиенту шлётся чанками `WriteTable` + задержка 10 мс. Клиент кэширует `DATA/minimap_rects_<map>.txt`.
- Рисует HUD: блюр, альфа по разнице высот, потолок (trace вверх), иконки NPC/дверей, конусы взгляда, трейл.
- Нужен **сгенерированный .nav**. Без него карта пустая.
- Тяжёлый `FindInSphere` каждый кадр + пузырьковая сортировка — для GRM не тащить как есть.

### 2. Ортофото (`map.lua`)
- Сервер меряет границы мира шагами `util.IsInWorld` от `info_player_*`.
- Клиент один раз `render.RenderView` сверху (`ortho=true`, камера с z=высота) → JPEG в `DATA/mapimages/<map>WxH.jpg`.
- Точки игроков: линейная нормализация `(pos-min)/(max-min)`.
- Плюс: одна текстура, дёшево. Минус: нет этажей, крыши перекрывают дворы, друзья только Steam friend.

### 3. GTA live RT (`gta5_minimap` / `gta5_fullmap`)
- Каждый кадр `PushRenderTarget` + `RenderView` с высоты 32000, yaw игрока, FOV=зум.
- Стрелка — картинка по центру (карта крутится под игрока).
- Fullmap: панорама с drag-offset и FOV-зумом.
- Плюс: живой рельеф. Минус: дорого, нет меток/этажей, HUD HP дублирует GRM.

### Уже есть в GRM
`sh_grm_minimap.lua` + stool `grm_minimap`: админские/личные метки, не «фото сверху».

**Вывод для GRM:** не подключать чужие аддоны в `lua/`. Если делать HUD-карту — ортокэш (2) + метки GRM, без navmesh-зависимости.

## Новости / фото (G-Typography)

Пайплайн:
1. Камера `weapon_typography_camera` — holdtype camera, зум ПКМ+мышь (`TranslateFOV`), ЛКМ → сервер шлёт `typo_camera_capture`.
2. Клиент `PostRender` + `render.Capture` JPEG, качество падает пока размер ≤ 45 КБ.
3. Диалог названия → upload raw bytes.
4. Сервер Base64 в `DATA/typography/photos/<sid64>.json`, лимит 32 кадра.
5. Принтер: чернила (entity cartridge), сессия+token 10 мин, дизайн JSON compress.
6. Печать: runtime issue (не диск) → entity газеты / стенд.
7. Картинка в вёрстке: `sourceType=photo` + `photoID`, при печати байты вшиваются в issue.

Нюансы:
- Нет привязки «на кого смотрел» — только кадр экрана.
- Remote URL картинок в конфиге есть, хосты пустые.
- Нет служебной почты и розыска.
- Дубликатор газет/чернил запрещён.

## GRM сейчас
- `sh_grm_news.lua` — текстовые статьи, без фото.
- Терминал: `attach_photo` пишет **путь** в `Wanted.Records.photoPath` (extra было 48 символов — мало).
- Физические документы — инвентарь, не JPEG.

## Что делаем в GRM
Служебная фотокамера + альбом + почта на ведомственный ПК + печать листа «ВНИМАНИЕ! РОЗЫСК!» + фильтры просмотра (ч/б, штамп, контраст как оверлей). JPEG на диск `data/grm_photos/`, в net только id и сжатый блоб.
