# ОТЧЁТЫ ВЛАДЕЛЯ И ЖУРНАЛ ПОДТВЕРЖДЁННЫХ ОШИБОК (GRMRP)

**Обязательно к прочтению каждому агенту ДО правок.** Единый MD по указанию
владельца (03.09 вечер-13): здесь — дословные отчёты, доказанные корневые
причины, принятые решения и правила. Не домыслы: каждая строка подтверждена
кодом/стендом. Новые записи добавляет каждый, кто чинит; молчать нельзя.

## 0. Постоянные приказы владельца (не пересматривать без него)

- (р.27, СТОЙКОЕ) Уведомления ленты: join/leave («Игрок X зашёл на сервер» /
  «Игрок X вышел с сервера» — default ВКЛ) и анонсы модерации «[МОДЕРАЦИЯ]
  Администратор X наказал игрока Y - <вид наказания>». ВИД НАКАЗАНИЯ — из
  таблицы PUNISH (lua/autorun/server/sv_grm_admin_actions.lua): она владелец
  слов, HUD выдумывать не вправе. Размеры читабельные (лента 19px/шаг 30),
  язык GRM (панели 8,14,23, амбра/красный акцент, Segoe UI), символы — только
  гарантированные шрифтом (WGL4): эмодзи и CJK-fullwidth в ленте запрещены —
  это тофу. Любой сбой модуля/пакета/моста не имеет права ронять чат или
  съедать сообщения: pcall на всех точках входа.

- (р.21, СТОЙКОЕ) ЧАТ — приоритет №1: работоспособный для сервера (отправка →
  результат показа → видимость чужих сообщений) + синхронизация с отыгровками
  и связанными модулями; библиотека — НОРМАЛЬНАЯ, ОБШИРНАЯ, по образцу
  Earu/EasyChat (автозагрузчик модулей, каталог, таги/фильтры, mentions,
  completion) — не 4 файла на 1800 строк.

1. Каждый раунд заканчивать: коммит → push в `arena/*` ветку сессии → **обе**
   dist-ссылки (`dist/grmrp_gamemode.zip` И `dist/grm_full_code.zip`).
2. Чат EasyChat вырезан ВЕЗДЕ (×4 повторений, вечер-13 финал): ни одного
   живого вызова `EasyChat.*` в контуре GRM. Осталось только в мёртвых
   комментариях-уроках — грепить СТРОКУ ВЫЗОВА, не слово.
3. Своя система: своя библиотека, свои правила, свои чаты. Все модули
   (документы, образование, спецслужба, бюллетени, обмен розыска, биндер,
   HUD) ходят через GRM-шины: `GRM.RPBroadcast`, `GRMRPChat.SendText/
   RegisterExternalChatCommand`, `GRM.Chat.DispatchFactory`. Не изобретать
   развилки заново в модулях.
4. Никаких выдумок об API движка: новый метод панели/скролла — только после
   грепа gsrc (garrysmod/lua). Подтверждённые фантомы см. §2 веч.-7/12.
5. Self-evidence оттиском сборки: жалоба «починено/не починено» закрывается
   штампом в баннере (`чат GRM · сборка вечер-N (дата)`), `/chatdiag`,
   `grm_money_diag`. Скриншот со старым оттиском = старая сборка, не баг.
6. «Зелёный стенд» ≠ «работает»: проверять БОЕВОЙ файл стендом, который его
   исполняет (sv-логику — sim_chat_sv_routing, грузящий реальный
   sv_grmrp_chat.lua). Статические грепы — только контракты/строки.
7. Нейрослоп запрещён: без мёртвых веток, дублей кода, условных проверок
   `x == 1 or true`, комментариев-отписок вместо логики, CJK-огарков и
   тайпо в именах проверок. Диф читается глазами перед коммитом.
8. Enter отправляет с первого нажатия; полоса ввода полностью видима;
   настройки = стандартный диалог движка; тик/клавиша в селекторе СРАЗУ
   меняют оружие; кнопки меню украшать, но не подменять функционал.
9. Деньги: наличка + счёт на постоянно видимом месте (кассеты «СОСТОЯНИЕ»
   v10.7+ и карточка меню «На счёту»); при жалобе сначала `grm_money_diag`.

- (вечер-14, СТОЙКОЕ) чат — отдельная библиотека `lua/grm_chat` по образцу
  EasyChat: тонкий лоадер + папка модулей; машиногенные дубли-порты
  недопустимы; режим ест библиотеку форвардерами/бандлом (байтовое равенство —
  гейт). Единственный источник кода — `lua/grm_chat/`.

- (р.29, СТОЙКОЕ) Меню паузы НЕ блокирует игровую консоль: ~ / Ё
  (toggleconsole, любой бинд) открывает консоль при открытом окне режима.
  Реализация веч.-27: окно НЕ забирает клавиатуру (SetKeyboardInputEnabled
  (false) — движковые бинды живут нативно; lua-прокси через RunConsoleCommand
  запрещён — ULib блокирует их [ULib] и это не обходится). Мышью владеет
  окно, ESC-сканер не зависит от захвата.
  Дополнение веч.-28 (заказ владельца): у режима ЕСТЬ своя «Консоль режима»
  (вкладка ESC-меню) — полный дубль ленты/ввода старой «Консоли сервера»
  (hook GRM_AdminConsoleLine + канал GRM.Admin.Net.CONSOLE + история
  GRM.Admin.ConsoleLines); пока открыта движковая консоль (gui.IsConsoleVisible),
  сканер и все окна режима отходят (своя консоль при этом гаснет), ESC
  закрывает сначала ВЕРХНЕЕ: консоль режима → меню → игра.
- (вечер-29, СТОЙКОЕ) Приказ владельца: кастомного меню паузы у режима НЕТ и
  быть не может («две меню паузы» на x86-64/Source Engine 24) — ESC целено
  движковому CEF-меню, ~ — нативной консоли. Файлы cl_grmrp_menu.lua и
  cl_grmrp_console.lua УДАЛЕНЫ; режим и библиотека чата gameui/ESC не трогают
  вовсе (HideGameUI запрещён во всех файлах). Админ-консоль — вкладка
  «Консоль» в /admin старого меню, DTextEntry без фантомов
  (SetBackgroundColor живёт только на DPanel; в файле токен под запретом).

- **веч.-27. Двойные уроки боевого лога.** (а) include чужой половины

- **веч.-25. Грейс-таймеры — костыль поверх гонки, а не решение.**

- **веч.-25. Два владельца одной клавиши = «не реагирует нигде».** ESC жил в
  root:OnKeyCodeTyped (нужен фокус) и в Takeover-хуке (грейс) одновременно;
  фокус движок отбирал — клавиша не доходила ни до кого. Клавишные сценарии
  режима держатся в одном Think-хуке, панель их не дублирует.

- **веч.-24. «Не отрисовывает» ≠ «нет данных» — проверь измерение, а не
  поток.** История получала полный архив, но перенос у C++ Label живёт от

  → «столбик по букве». Текстовые окна м.явный расчёт (WrapText через

- **веч.-24. Оптимистичное эхо — ложь на отказе.** Локальный показ до
  вердикта сервера уместен болтовне, но НЕ лимитируемым каналам: «сообщение

  cooldown — эхо только от сервера (includeAuthor), отказ = ни строки, ни
  отправки (зеркало кулдауна в клиенте).
- **веч.-24. Чужой фокус — чужой ESC.** Пока окно живёт без keyboard-владения,
  закрытие по ESC обязан обеспечивать верхний фокус (меню) или Think-страховка;
  «вернуть keydown false» без адресата = «не закрывает ничего».

- **веч.-23. «Функционал не подменять» = ходить КАНОНОМ ДВИЖКА, а не
  числом кадров.**
  и не retry-счётчиком наугад, а контрактом: gui.ActivateGameUI (глобалка,

- **веч.-23. Рефактор порядка вызовов ломает «тихий» контракт грации.**
  Перенос флагов перед Menu.Close() вернул баг: Close переставляет
  justClosedRT и грейс глушил только что открытую gameui. Рантайм-стенд
  с управляемым временем (sim_esc_menu_flow) поймал это сразу — статический
  grep бы нет.

- **веч.-22b. Цикл загрузки без изоляции файлов = мина смешанных
  установок.** owner-флоу «пролить зип поверх папки» легален только когда
  загрузчик терпит лишние файлы. Голый include в цикле gamemode-входа
  превращает ЛЮБОЙ устаревший файл в «исчезнувший UI целиком». Канон:
  pcall-на-файл + сводная строка «какие файлы пропущены» — самодиагностика
  без допроса лога.
- **веч.-22b. Дрейф API ловится срезом, не памятью.** «Меню зовёт
  GRMRPChat.pushSystem, которого веч.-21 больше не экспортирует» обнаружилось
  механически: все внешние GRMRPChat.* против списка экспорта библиотеки
  (comm). Любая реформа API обязана прогонять этот срез.
- **веч.-22. Уведомление — не новый пайплайн.** Лента уже принимала
  chat.AddText (мост веч.-13), админка уже звала AD.Announce всем. «Добавить
  уведомления в чат» означало: дать PUNISH существительные видов и владельческий
  формат (владелец слов — модуль админки!) и научить мост различать
  [МОДЕРАЦИЮ] (красный тег ленты). Второй net-канал под это — верный путь к
  дублям и «своей системе, которая не в системе».
- **веч.-22. Дубль анонса ищется по графу вызовов, не по тексту.** A.serverban
  зовёт SB.Ban, а SB сам анонсировал — после внедрения PUNISH-строки лента
  получила бы две красные строки на одно событие. Лечение: opts.silent у
  SB.Ban/Unban (антчит/консоль анонсируют как прежде), PUNISH — единственный
  анонсёр из AD.
- **веч.-22. Символы ленты ограничены WGL4.** GMod линкует шрифт целиком, не
  по глифам: 🙂/📩/✦ в Segoe UI = квадраты, ＜＞ (CJK) — чужая гарнитура.
  Эмодзи-замена сужена до гарантированных ☺♥≡↑↓→; нейтрализация разметки
  переехала с полнотекстных скобок на ‹ ›. Стена clocks не даёт тофу
  вернуться (ни в коде, ни в комментариях ядра — скан всего файла).
- **веч.-21. UTF-8 фолдинг — свой, а не string.lower.** В Lua 5.1
  string.lower НЕ трогает кириллицу, а в GMod трогает — расхождение «стенд
  зелёный, бой красный». LowerFold (ASCII + D0/D1-кириллица, включая Ё и
  границу D0→D1 для Р..Я) исполняется идентично и там, и там; стенд ловит
  регистровые баи (С=D0 A1 → с=D1 81!).
