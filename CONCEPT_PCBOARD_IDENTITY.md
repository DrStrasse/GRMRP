## 2. Идентификаторы: ID игрока и ID персонажа

Сейчас ключи технические (`76561198…:char2`) — в чат и в справку такое не
покажешь. Вводим короткие RP-номера.

```
GRM.Registry (новый модуль sh_grm_registry.lua)
  data/grm_identity/registry.json
  {
    accounts = { ["76561198…"] = { pid = 1042, first = 1723... } },
    chars    = { ["76561198…:char2"] = { cid = 4821, pid = 1042,
                                          created = ..., name = "Ганс Мюллер",
                                          retired = false } }
  }
```

* **PID (ID игрока)** — номер аккаунта, 3–5 цифр. Один на человека, не
  меняется. Видят: администрация, спецслужбы, журналы. Это «служебный» номер.
* **CID (ID персонажа)** — номер персонажа, он же **личный номер гражданина**
  в госреестре. Печатается в паспорте, звучит в РП, по нему ищет `/pcboard`.
* Номера выдаются последовательно при первом входе персонажа и **никогда не
  переиспользуются** (удалили персонажа — номер уходит в архив `retired`).
* API: `GRM.Registry.CID(ply|charKey)`, `.PID(ply)`, `.ByCID(number)`,
  `.Resolve(query)` (принимает CID, имя, SteamID — для админов).
* NW на игроке: `GRM_CID`, `GRM_PID` (PID отдаётся только тем, у кого право).

Почему два номера: игрок один, персонажей до трёх. Полиция ловит **персонажа**
(CID), администрация банит **игрока** (PID). Смешивать их в одном номере —
классическая дыра метагейма.

## 3. Шапка над головой v3 (объединяем два HUD в один)

Сейчас над головой рисуют **два независимых `HUDPaint`** (rpdesc и фракции),
каждый со своим радиусом и своей плашкой — отсюда «прыгающие» подписи, двойные
фоны и лишние проходы по всем игрокам каждый кадр.

Предложение — единый модуль отрисовки `GRM.Nameplate`:

```
┌───────────────────────────────┐
│  Ганс Мюллер            #4821 │  ← имя (или «Неизвестный»), CID по настройке
│  [ПД | СВАТ] Сержант          │  ← тег организации + должность (на службе)
│  «Хромает на левую ногу»      │  ← rpdesc, до 3 строк, курсив
└───────────────────────────────┘
```

Правила:
1. **Один проход и один кэш** на кадр (через `GRM.Perf.Players`), одна плашка,
   общая дистанция `grm_cl_nameplate_dist`, плавное затухание.
2. **Имя показывается не всем и не всегда.** Варианты (конвар сервера):
   * `open` — как сейчас, имя видно всем;
   * `acquainted` — имя видно, если персонажи «знакомы» (обменялись
     документами/визитками) либо если у смотрящего есть допуск;
   * `docs` — незнакомым видно «Неизвестный (муж., ~30 лет)», имя открывается
     после показа паспорта.
   Рекомендую начать с `open`, но заложить механику сразу — она даёт смысл
   паспорту и `/pcboard`.
3. **Маскировка**: если персонаж под легендой (covers) — показывается легенда,
   а `/pcboard` по нему даёт пометку «личность не установлена».
4. **Роль и тег** — из готовой `GRM_ChannelTag` (уже сделано 19.08), только
   когда сотрудник **на службе** (`GRM.FactionDuty`), иначе — гражданский вид.
5. **CID над головой** — отдельная настройка: `никогда / только своим
   госслужащим на службе / всем`. По умолчанию — только госслужащим.
6. Мёртвые/в бессознанке — плашка меняется на «тело» (совместимо с медициной).

`rpdesc` при этом остаётся и улучшается: редактор в стиле GRM, деление на
«внешность» (видно всем) и «особые приметы» (видно только при осмотре
`/search` или по `/pcboard`).

## 4. ID в чате и фракциях

* **IC-чат** номер НЕ показываем (иначе метагейм: «эй, #4821!»).
* **Служебные каналы** (`/fr`, `/frb`, `/dep`, `/d`, `/db`, `/depb`) — рядом с
  тегом можно добавить CID говорящего: `[ПД | СВАТ | #4821] Сержант Мюллер`.
  Управляется конваром, по умолчанию **включено** только для госканалов.
* **OOC/админ-чат** — PID для администрации (`(#PID 1042)`), чтобы админ видел
  игрока, а не персонажа.
* **Фракции**: в составе организации (`/factions` → «Сотрудники») колонка «ID»
  с CID; поиск по номеру. В кадровых делах номер печатается в досье.
* **Документы**: CID печатается в паспорте, ксиве, военном билете — тогда
  «пробитие по базе» и «проверка документа» сходятся по одному номеру.

## 5. `/pcboard` — планшет госслужащего

### 5.1 РП-логика
Сотрудник достаёт планшет, вводит человека в базу, ждёт несколько секунд,
получает справку **только себе в чат**. Окружающие видят системное РП-действие:

```
** Сержант Ганс Мюллер достаёт служебный планшет и пробивает человека по базе данных.
```

Через 2–4 секунды (настраивается) — второе действие и результат:
```
** Планшет Сержанта Мюллера коротко пиликает — запрос обработан.
[ГОСБАЗА] Справка по лицу #4821 …   ← видит только запросивший
```

### 5.2 Способы запроса
| Команда | Что делает | Требование |
|---|---|---|
| `/pcboard` | по человеку в прицеле (до 200 юн.) | базовый допуск |
| `/pcboard #4821` | по номеру в базе | право «поиск по номеру» |
| `/pcboard Ганс Мюллер` | по имени (список совпадений) | право «поиск по имени» |
| `/pcboard авто <номер>` | владелец транспорта (из дилера/гаража) | право «транспорт» |
| `/pcboard я` | своя карточка, что видят другие | всем |
| `/pcboard журнал` | последние 20 своих запросов | всем с допуском |

Плюс кнопка в служебных компьютерах (`grm_comp_police`, `grm_comp_military`) и
в контекстном C-меню на прицеленном игроке — та же функция, один код.

### 5.3 Условия использования
* Сотрудник **на службе** (`GRM.FactionDuty`) и его организация имеет допуск;
* планшет как предмет инвентаря — опционально (галочка в настройках: «требовать
  предмет `grm_item_tablet`»), по умолчанию выключено, чтобы не ломать текущий
  геймплей;
* цель — живой игрок в радиусе (для прицельного режима) либо номер в базе;
* кулдаун 8 с на запрос, 3 запроса в минуту, лимит защищён `GRM.Net.Guard`;
* **всё пишется в журнал** (`data/grm_pcboard/log.json` + `GRM.Audit`): кто,
  кого, каким уровнем, когда. Журнал смотрят суперадмины и начальство
  организации (право `pcboard.audit`). Это ключ против «пробью-ка я всех».

### 5.4 Уровни допуска (расширяю вашу схему)

| Уровень | Кому | Что видит |
|---|---|---|
| **0. Нет** | все прочие | ничего, команда недоступна |
| **1. Правоохранительный** | Полиция Порядка, патруль | Имя, пол, CID, гражданство, статус розыска и уровень, действующие статьи, непогашенные штрафы, В/У гражданское и его статус, лицензия на оружие, судимости (архив) |
| **2. Комендатура** | Фельджандармерия, ВАИ | Имя, пол, CID, военный билет (серия/номер), воинское звание и подразделение, статус воинского учёта (служит/запас/не служил/уклонист), военное В/У, допуск к оружию по линии ВС, воинские правонарушения |
| **3. Спецслужбы** | Гестапо/СБ | Всё из 1 и 2 + место работы (организация, отдел, подотдел, должность), недвижимость и транспорт на имени, образование и дипломы, медкарта (кратко), легенды прикрытия и поддельные документы (флаг «личность под легендой»), последние 5 пробитий этого лица другими службами |
| **A. Администрация** | суперадмин | всё + PID игрока, SteamID, история персонажей аккаунта |

Дополняю вашу схему тремя вещами, которых не хватало:

1. **Медицина (уровень 1, кратко)** — «есть действующая справка о годности»,
   группа крови; полная медкарта только у медиков и спецслужб (медики получают
   свой профиль допуска — «Медицинский»: имя, CID, группа крови, аллергии,
   травмы, вакцинация; без розыска и без военного билета).
2. **Профиль «Пограничный/Таможня»** (если пригодится) — имя, CID,
   гражданство, разрешения на въезд, судимости кратко.
3. **Тонкая настройка**: уровень — это пресет, а поверх него в `/factions`
   галочками включаются/выключаются отдельные блоки. То есть можно выдать
   Полиции стандартный «Правоохранительный», а конкретному отделу дополнительно
   открыть блок «транспорт».

### 5.5 Как настраивается (в `/factions`)
Новая вкладка **«Госбаза (pcboard)»** рядом с «Правами меню»:
* уровень допуска организации: нет / правоохранительный / комендатура /
  медицинский / спецслужбы;
* уточнение по **отделу и подотделу** (наследуют уровень организации, можно
  переопределить) и по **должности** — тем же деревом, что уже сделано для
  категорий дверей 19.08;
* галочки блоков поверх уровня (розыск, штрафы, В/У, военный билет, транспорт,
  недвижимость, образование, медкарта, легенды, журнал пробитий);
* «требовать нахождения на службе», «требовать предмет-планшет», кулдаун,
  время «пробития», текст РП-действия;
* право `pcboard.audit` — кто видит журнал запросов.

Хранение: `data/grm_pcboard/access.json`, формат и приёмы — как в
`sh_grm_faction_menu_access.lua` (проверенный слой, дублировать не будем).

### 5.6 Архитектура: провайдеры данных
`/pcboard` **не лезет** внутрь модулей. Каждый модуль регистрирует провайдера:

```lua
GRM.PCBoard.RegisterProvider("wanted", {
    label   = "Розыск и правонарушения",
    fields  = { "wanted.level", "wanted.articles", "wanted.fines" },
    levels  = { police = true, special = true },   -- кому доступен блок
    collect = function(charKey) ... return rows end,
})
```

Провайдеры: `identity`, `documents`, `wanted`, `fines`, `military`,
`licenses`, `education`, `medical`, `employment`, `vehicles`, `property`,
`covers`, `history`. Если модуля нет на сервере — блок просто не появляется
(как сделано с буром в шахте). Это же даёт бесплатное расширение: появится
новый модуль — зарегистрирует свой блок сам.

### 5.7 Вывод справки
Компактная карточка в чат (цвета GRM, как служебные каналы), плюс, по желанию,
окно с тем же содержимым (кнопка «открыть подробно») — окно удобнее для
спецслужб, где полей много:

```
[ГОСБАЗА] СПРАВКА · #4821
Ганс Мюллер · муж. · гражданин
Розыск: 2 уровень — «Нападение на сотрудника», «Хранение оружия»
Штрафы: 2 непогашенных, 12 400 GRM
В/У: гражданское, действует · Оружие: разрешение №77-21
Воинский учёт: служил, запас · Военный билет: ВС-4412
Запрос: Сержант Мюллер (ПД | СВАТ), 19.08 21:14
```

### 5.8 Защита от абьюза (важно)
* журнал + право на его просмотр начальством и админами;
* видимое `/me` — нельзя пробивать «незаметно» (кроме спецслужб: у них опция
  «скрытый запрос», но он **всегда** пишется в журнал и виден админам);
* кулдаун и лимит в минуту;
* пробитие человека **под легендой** возвращает данные легенды, а не реальные,
  и помечается — иначе система убивает всю игру в шпионов;
* нельзя пробивать себя чужим уровнем (только `/pcboard я`);
* результат уходит **только запросившему** (`net.Send`, не broadcast).

## 6. Этапы (каждый — отдельный ход, со стендами)

1. **Реестр ID** (`GRM.Registry`): PID/CID, файл, NW, API, печать номера в
   документах. Стенды: выдача номеров, уникальность, архив, миграция
   существующих персонажей.
2. **Шапка над головой v3**: объединение двух HUD, режимы видимости имени,
   маскировка, CID по настройке, новый редактор `rpdesc`. Стенд: логика
   видимости (кто что видит), отсутствие второго `HUDPaint`.
3. **ID в чате и фракциях**: служебные каналы, состав организации, досье.
4. **`/pcboard` ядро**: провайдеры, уровни, РП-действие, кулдаун, журнал,
   вывод в чат. Стенды: матрица допусков (кто какие поля получает), легенды,
   лимиты, журнал.
5. **Вкладка «Госбаза» в `/factions`** + право `pcboard.audit` + окно
   подробной справки + кнопки в служебных компьютерах.

## 7. Решения владельца (19.08) и статус

| Вопрос | Решение |
|---|---|
| Имя над головой | «Неизвестный» до предъявления документа |
| CID в служебных каналах | показывать |
| Планшет как предмет | не нужен, достаточно быть на службе |
| Медики | свой профиль допуска |
| Скрытый запрос спецслужб | разрешён (с записью в журнал) |
| Формат номера | с префиксом: `ГР-####` (персонаж), `ИГ-####` (игрок) |

Статус по этапам:

* **Этап 1 — реестр ID: СДЕЛАНО** (`sh_grm_registry.lua` v1.0.0). Номера
  выдаются последовательно с 1000, не переиспользуются, живут в
  `data/grm_identity/registry.json`, висят на игроке (`GRM_CID`, `GRM_PID`),
  ищутся по номеру/имени/SteamID, принимают латинскую раскладку префикса.
  Номера подключены к служебным каналам, к составу организации (колонка «ID»
  и поиск) и к админ-панели (бан по ID игрока, в том числе офлайн).
* **Этап 3 — ID в чате и фракциях: СДЕЛАНО** вместе с этапом 1.
* **Этап 4 — ядро `/pcboard`: СДЕЛАНО** (`sh_grm_pcboard.lua` v1.0.0).
  Уровни допуска считаются по цепочке организация → отдел → подотдел →
  должность, поверх уровня — галочки блоков в трёх состояниях
  («по уровню» / «включить» / «выключить»). Данные собирают 13 провайдеров
  из уже существующих модулей (личность, розыск, штрафы, удостоверения,
  воинский учёт, место службы, транспорт, недвижимость, образование,
  медкарта, легенды, кто пробивал раньше, служебные данные аккаунта).
  Нет модуля на сервере — блок просто не появляется. Справка уходит
  `net.Send` только запросившему, окружающие видят два РП-действия
  («достаёт планшет» и «планшет пиликает»), скрытый запрос доступен
  спецслужбам и всё равно пишется в журнал. Кулдаун, лимит запросов в
  минуту, журнал `data/grm_pcboard/log.json` + `GRM.Audit`, право
  `pcboard.audit`. Команды: `/pcboard`, `/пробить`, `/pcboard <номер|имя>`,
  `/pcboard авто <номер>`, `/pcboard я`, `/pcboard журнал`,
  `/pcboard скрытно …`, консоль `grm_pcboard`, `grm_pcboard_log`.
* **Этап 5 — вкладка «Госбаза»: СДЕЛАНО** (`cl_grm_pcboard_ui.lua`).
  Слева дерево организации, справа уровень узла и галочки блоков; внизу
  кулдаун, лимит, время пробития, «только на службе», «скрытый запрос
  спецслужбам». Справка печатается в чат, по `grm_pcboard_window` (или
  конвару `grm_cl_pcboard_window 1`) открывается тем же содержимым окном.
* **Уровни «Юстиция» и «Пожарная служба»: ДОБАВЛЕНЫ (21.08)**.
  «Юстиция» (суд, прокуратура, надзор): личность, приметы, розыск и статьи,
  штрафы, удостоверения и лицензии, воинский учёт, место службы, транспорт,
  недвижимость, образование и журнал «кто пробивал это лицо». Медкарта и
  легенды прикрытия закрыты (включаются галочкой).
  «Пожарная служба»: личность, приметы, недвижимость (владелец горящего
  объекта — главное на выезде) и медкарта для первой помощи. Розыск, штрафы,
  воинский учёт и транспорт закрыты. Скрытый запрос остаётся только у
  спецслужб и администрации.

* **Этап 2 — шапка над головой v3: СДЕЛАНО** (`sh_grm_nameplate.lua` v1.0.0).
  Два `HUDPaint` (описание из `sh_grm_rpdesc.lua` и шапка организаций из
  `sh_factions.lua`) заменены одним: одна плашка, один радиус, один проход
  по игрокам, кэш переноса строк. Имя незнакомым не показывается —
  «Неизвестный (муж.)» до знакомства; знакомство даёт `/представиться`
  (все рядом), `/паспорт` (только тому, кому показали) и успешное пробитие
  через `/pcboard`. Знакомства односторонние и хранятся в
  `data/grm_identity/acquaintance.json`. Под легендой показывается
  прикрытие, и знакомство не записывается. Тег организации и должность
  видно только на службе, номер ГР — по настройке
  (`never` / `gov` / `all`). Особые приметы (`/приметы`) над головой не
  показываются: они видны в справке `/pcboard` отдельным блоком.
  Режимы: `grm_nameplate_mode` (open / acquainted / docs),
  `grm_nameplate_cid`, `grm_nameplate_gov_names`, `grm_nameplate_intro_dist`.
* **Кнопки `/pcboard` в служебных компьютерах: СДЕЛАНО** — вкладка «Госбаза»

  второй реализации запроса нет.

## 8. Старые вопросы (закрыты решениями выше)

1. **Видимость имени над головой** — оставляем «всем видно» или вводим
   «неизвестный до предъявления документа»? Это сильно меняет ощущение игры.
2. **CID в служебных каналах** — показывать номер говорящего или только в
   справке?
3. **Планшет как предмет** — нужен ли физический предмет в инвентаре, или
   достаточно быть на службе?
4. **Медики** — делаем им отдельный профиль допуска (я предлагаю да) или
   медкарта только у спецслужб?
5. **Скрытый запрос спецслужб** — разрешаем (с записью в журнал) или РП-действие
   обязательно для всех?
6. **Номера**: сквозная нумерация с 1000 (как «личный номер гражданина») или
   формат вида `ГР-4821` / `ВС-1120` по категории?
