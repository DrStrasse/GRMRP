# ANALYSIS — HLX_Books (читаемые книги с Markdown, плагин Helix)

**Дата:** 2026-08-16 · **Источник:** https://github.com/sunmoonyan/HLX_Books (46 файлов, 339 КБ)
**Назначение для GRM:** эталон того, как в GMod делается «книга/документ с
разметкой» — прямо под наш заказ «документы» (свой GRMML мы удалили, это —
готовый зрелый образец рендера и редактора).

## 2. Markdown-движок (`cl_book.lua`) — самое полезное для GRM

Функции по порядку:
- `Tokenise(text, baseFontName, baseColor, pal)` — **инлайн-токенизатор**:
  стеки цвета/шрифта/ссылки (`colorStack/fontStack/linkStack`), `earliest(str,pos)`
  ищет ближайший спец-маркер.
- `ParseToCommands(raw, contentW, palIn)` — **блочный парсер** в команды отрисовки:
  заголовки `#/##/###`, `> цитаты`, `- списки`, `| таблицы`, ` ```code``` `,
  `[hr]`, `[chart:…]`, `[image:url]`, абзацы. Результат — список `{h, fn}`.
- Свои теги разметки: `[color:red]`, `[font:Courier New]`, `[link:https://…]`.
- `DrawTokens / WrapLine` — перенос строк с учётом ширины шрифта.
- **18 цветовых слотов** + **8 пресет-тем** (палитра `BookPalette(cfg)`).
- Двухстраничный режим, навигация стрелками/A-D, копирование кода в буфер.
- Картинки обложек/в тексте — `http.Fetch` с кешированием (`GetImage(src)`).

### 2.1 Что перенимаем (паттерны)
1. **Конфиг книги = данные предмета** (`ITEM.bookTitle/bookContent/…`), а не
   жёсткая структура. Клиент рисует по `cfg` с фолбэками (`SafeString/SafeBool/
   SafeColorTable`).
2. **Парсер в два слоя**: инлайн-токенизация внутри блочного парсера. Это ровно
   та же идея, что была в нашем удалённом `GRMML` (блоки + инлайн), но доведённая
   до ума: таблицы, код-блоки, графики, ссылки, картинки.
3. **Редактор = VGUI с живым превью** и пикерами цвета — вместо голого текстового
   поля. Наш `/doc_admin` и «служебный терминал» могли бы использовать это.
4. **Архив книг** (`sh_archive.lua`): определение книги → постоянный тип предмета
   (`ix.item.Register`), админ-панель «дать/спавнить/удалить». Аналог нашему
   «шаблону документа» (`DOC.Templates`), но для книг.

## 3. Релевантность к заказам GRM

- **Документы (паспорт/ксива/права)**: идея «предмет = данные + рендер по конфигу»
  совпадает с нашим `DOC.Registry` + `openXxxUI`. Разница — HLX рендерит Markdown,
  у нас фиксированный бланк. Можно добавить «книги» как отдельный тип документа.
- **Рендер**: если вернём разметку документов — взять за основу `Tokenise +
  ParseToCommands` (уже отлаженный, с таблицами/кодом/темами).
- **Лицензия**: MIT/GPL — проверить заголовок перед копированием (в README лицензия
  не указана явно, уточнить при переносе кода).

## 4. Вывод
HLX_Books — компактный (2.2к строк) и законченный пример «книга с Markdown» в
GMod. Это **готовый чертёж** для раздела «документы/книги» GRM. Переносить стоит
**идею и структуру парсера**, адаптировав под нашу палитру/темы GRM, а не копировать
файлы один в один (зависит от Helix-ядра `ix.*`).
